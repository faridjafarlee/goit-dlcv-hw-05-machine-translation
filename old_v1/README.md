## Налаштування

- Пара мов: німецька → англійська. Обидві мови підтримуються spaCy, а через інший порядок слів у німецькій аналіз уваги має сенс.
- Дані: без дублікатів пар → 3-25 слів з обох боків → співвідношення довжин en/de 0.5-2 → унікальне німецьке речення → перемішування (seed 42) → ≤ 30 токенів spaCy; train 150 000 / val 3 000 / test 3 000 (≈ 7.6 % корпусу).
- Токенізація: правилові токенізатори `spacy.blank('de')` / `spacy.blank('en')` (той самий токенізатор, що в `de_core_news_sm` / `en_core_web_sm`), нижній регістр, `<sos>` / `<eos>`.
- Словники: власний клас `Vocab` на `Counter` (замість застарілого `torchtext`), `min_freq = 5`, спецтокени `<unk>=0, <pad>=1, <sos>=2, <eos>=3`.
- DataLoader: `pad_sequence` (форма `(seq_len, batch)`) і bucket-семплер. У батчі опиняються речення схожої довжини, тому частка `<pad>` ≈ 1-2 % замість ≈ 40 %.
- Модель (як у практиці теми 12, bentrevett / Bahdanau): ембединги 256, двонаправлений GRU-енкодер 512, адитивна увага, GRU-декодер 512, `fc_out([s_t; c_t; emb])`. Відносно лекції додано маску `<pad>` в увазі та dropout 0.3 на ембедингах. Ініціалізація N(0, 0.01).
- Навчання: `CrossEntropyLoss(ignore_index=<pad>)`, Adam lr 1e-3 + `ReduceLROnPlateau(0.5)`, clip grad norm 1.0, teacher forcing 0.5, batch 128, до 8 епох (early stopping 3); найкращі ваги вибираються за val loss (TF = 1.0).
- Оцінка: loss / perplexity у режимах TF = 1.0 і TF = 0.0 (як у лекції), BLEU / chrF (`sacrebleu`, токенізований текст у нижньому регістрі), greedy vs beam search (k = 5, length penalty 0.7), BLEU за довжиною речень, кількісні метрики уваги (гострота, ентропія, монотонність, вага на `<eos>`).

## Відхилення від лекційного коду / інструкції

- `torchtext` не використовується, бо він несумісний з torch 2.x. Замість нього власний словник з тим самим API (`lookup_indices`, `lookup_tokens`).
- Токенізатори `spacy.blank` замість завантаження `*_core_*_sm`: токенізація ідентична, але швидша.
- Маска `<pad>` в увазі, dropout на ембедингах, bucket-семплер і `ReduceLROnPlateau` дають невеликі покращення, вони описані в ноутбуці.
- У лекції train loss (TF = 0.5) і val loss (TF = 0.0) порівнювали напряму. Тут train-підвибірка й validation оцінюються однаково (TF = 1.0 і TF = 0.0).
- Захист від NaN у `train_fn` і чекпойнт після кожної епохи. Спільний GPU (MPS) під навантаженням інших задач іноді аварійно переривав GPU-команди, і перша спроба навчання (батч 256) «зламалась» у `nan`.
